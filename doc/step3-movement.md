# Step 3 — 走行とタイミング式3段ジャンプ

実施日: 2026-10-16

状態: Step 3完了。専用練習マップと入力を作成し、3種類の時間刻みで動作を確認した。

## 操作とルール

| 操作 | キー |
| --- | --- |
| 移動 | WASD |
| 視点 | マウス |
| 走る | 左または右Shiftを押している間 |
| 1段目のジャンプ | 地上でSpace |
| 2・3段目 | Spaceを離し、各段の頂点付近で押し直す |

2・3段目の受付は、直前のジャンプの予測頂点時刻の前後0.15秒。早すぎる・遅すぎる入力では段数を消費しない。早押し後も、離して有効なタイミングで押し直せば次段を出せる。受付時間を過ぎた場合は着地して再挑戦する。

長押しでは次段が自動発動しない。4段目は出ない。着地すると段数を0に戻すが、Spaceを押したままでも自動的には跳ね直さない。崖から歩いて落ちた状態では1段目を開始できない。

画面左上に段数、歩行／走行、水平速度、早押し／遅押し等のフィードバックを表示する。白いマーカーが緑の帯に入ると **SPACE NOW!** が表示される。表示はStep 3用の仮HUD。

## 実装

- `NinjaCharacter.*`: 既存Third Personキャラクターから派生。通常の移動とカメラを利用し、ジャンプ・走行を追加した。
- `NinjaTrainingHUD.*`: 段数とタイミングをCanvasに描画する。
- `NinjaMovementCheck.*`: `-NinjaMovementCheck` 指定時だけ動く検証Actor。通常プレイではTickを無効化する。
- `Content/Ninja/Blueprints/BP_NinjaCharacter`: 元のキャラクターBlueprintを複製し、専用C++クラスへ親を変更。既存のメッシュ・アニメーション・カメラ設定を利用する。
- `BP_NinjaTrainingGameMode`: 専用キャラクターとHUDを指定する。
- `Content/Ninja/Input/IA_Sprint`、`IMC_NinjaSprint`: 専用のShift入力。既存のWASD・Space入力と合わせて利用する。

元のThird Person C++クラスでは、ジャンプ入力を `DoJumpStart` / `DoJumpEnd` に通すように変更した。基底クラスの処理は従来どおり `Jump` / `StopJumping` であり、Ninja側の仮想関数で専用の処理へ切り替える。

### 初期調整値

| 項目 | 設定 |
| --- | --- |
| 歩行 | 700cm/s（7m/s） |
| 走行 | 1,400cm/s（14m/s） |
| 1段目の上向き速度 | 1,100cm/s |
| 2段目 | 1,700cm/s |
| 3段目 | 2,300cm/s |
| GravityScale | 1.5（標準重力で下向き1,470cm/s²） |
| AirControl | 0.65 |
| 次段の受付時間 | 予測頂点の前後0.15秒 |

次段が成立すると鉛直速度を指定値へ更新し、水平速度を保つ。ジャンプキーを離した長さで高度は変わらない。地図上の建物高さと移動経路を決めるStep 4以降で調整できるよう、速度・上向き速度・受付時間はBlueprintのデフォルトから編集できる。

## 練習マップ

`Content/Ninja/Maps/L_NinjaTraining.umap`

- 200m四方の床。
- 高さ10m・20m・30mの箱を別々のレーンに配置。
- 建物の進行方向の幅は10m。踏み切り位置付近から45〜55m先にある。
- 開始レーンは10mの建物。30mのレーンは横方向に移動すると試せる。
- 操作確認は灰色のテスト環境で行う。池袋マップへの専用操作の統合はStep 4以降。

まずShift＋Wで速度をつけ、開始地点付近からSpaceで跳ぶ。以降は頂点で2・3段目を出す。30mの建物では踏み切る場所が重要。壁へ早くぶつかると横方向の勢いが落ち、屋上に着地することがある。

初回の検証では、幅20m・手前35mの30m建物に上昇途中で衝突し、屋上への着地になった。その結果を踏まえ、到達高度と水平位置を合わせてコースを配置し直した。3段ジャンプの能力だけで全てのビルを無条件に越えられる設計にはしていない。

## 検証方法

1. `Tools/Editor/Build-Step1.ps1` でエディタ用C++をビルド。
2. UE PythonScript commandletで `Tools/Editor/setup_step3.py` を実行し、専用Blueprint・入力・練習マップを作成。
3. `Tools/Editor/Verify-Step3.ps1 -FPS 30`、`-FPS 60`、`-FPS 120` を実行。

検証は `PlayerController::InputKey` からW・LeftShift・Spaceのキーイベントを入れ、実際のEnhanced Input設定と入力バインドを通す。ジャンプ関数の直接呼び出しだけで成功とはしない。

FPSの比較はUEの固定時間刻みを30・60・120Hzに設定した**シミュレーションの比較**。実際の描画fpsや処理性能のベンチマークではない。物理キーボードでの操作感は試遊で確認する。

検証するケース:

1. Wで歩行速度になり、Shiftで走行速度になる。
2. Spaceを押したままでも1段だけで終わり、着地後に自動再ジャンプしない。
3. 頂点より早すぎる入力が不発になる。
4. 頂点より遅すぎる入力が不発になる。
5. 適切なタイミングで3段まで出せ、4段目は不発になる。
6. 通常ジャンプでは30mの壁に止められる。
7. 走行＋3段ジャンプで30mの建物の向こう側へ出て、床に着地する。

着地後の段数リセットは各ジャンプケースで検証する。最後の建物越えでは、屋上に乗っただけでは成功と判定しない。
