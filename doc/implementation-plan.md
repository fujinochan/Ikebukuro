## 1. 完成させるゲーム

池袋駅周辺を黒い忍者で走り、タイミングを合わせた3段ジャンプで建物を越えながら、赤い忍者を倒す三人称視点のミニゲーム。1プレイは最大5分とする。

### ユーザー指定の要件

- 約5分で終わる単純なミニゲーム。
- 主人公は黒い忍者。走る・ジャンプ・タイミングによる最大3段ジャンプができる。
- 上手にジャンプすればビルを越えられる。
- 直進する手裏剣を投げられる。
- `13116_toshima-ku_pref_2025_3dtiles_mvt_1_op.zip` の3D都市データから、池袋駅周辺の一部をプレイエリアとして使う。
- 赤い敵忍者を、踏みつけまたは手裏剣の命中で倒す。

### 初期実装で採用する仮仕様

| 項目 | 初期案 |
| --- | --- |
| 対象 | Windows PC、1人用、キーボードとマウス |
| 制限時間 | 操作開始から300秒。ポーズ中と開始前のロード中は停止 |
| 勝利 | 固定配置した敵8体を全滅させる |
| 敗北 | 時間切れ、または主人公の体力が0になる |
| 主人公の体力 | 3。敵との側面接触で1減少、被弾後は短い無敵時間 |
| 落下・範囲外 | 体力を1減らし、安全な復帰地点に戻す。残り時間と撃破数は維持 |
| 敵の耐久力 | 踏みつけ・手裏剣のどちらも1回で撃破 |
| 手裏剣 | 弾数無制限、投射間隔あり、重力なし、追尾なし、貫通なし |
| ステージ | 池袋駅周辺の約400m四方を候補にする。実際の範囲はデータと移動速度の検証後に決定 |
| 所要時間 | 初見のクリア目標3〜5分。上達すると短縮できる |

初期版は1ステージ、1種類の敵、2種類の倒し方に絞る。ボス、オンライン対戦、建物内部、複雑な成長システムは完成後の拡張候補とする。

- 初期マップは `Content/ThirdPerson/Lvl_ThirdPerson.umap`。

- `Variant_Platforming` に二段ジャンプ・壁ジャンプ・ダッシュのサンプルがある。ただし今回必要な「タイミングで3段ジャンプ」とは異なるため、仕組みを参考にして専用実装する。

- `.uproject` のプラグイン一覧に Cesium は明示されていない。マシンへのインストール状況と UE 5.8 対応は実装開始時に確認する。
- 描画設定には Lumen / Ray Tracing 等があり、Hardware Targeting は Mobile。Windows向けの性能検証時に意図を整理する。
- この作業フォルダでは Git リポジトリを確認できなかった。

### ZIP の中身

ZIP は約701 MB（701,027,241 bytes）、9,167エントリ。展開せずディレクトリと建物 LOD1 などの `tileset.json` を読んで確認した。

| 内容 | 確認結果・使い方 |
| --- | --- |
| 建物 | `bldg_3dtiles_13116_toshima-ku_lod1`、`lod2`、`lod2_no_texture` がある |

## 3. 実装方針と構成

### 地図の扱い

第一候補は Cesium for Unreal によるローカル3D Tilesの読み込み。公式資料にはローカルの `tileset.json` を `file:///` URL で読み込む手順がある。ただし、**UE 5.8 と採用するプラグイン版の組み合わせで、表示・衝突・パッケージ動作を最初に検証する**。現時点では互換性を確定していない。

池袋駅付近に地理座標の基準点を置き、街とキャラクターを同じローカル座標で扱う。UE側の cm と地理データの m、軸方向、標高を検証する。ゲーム中は基準点を固定して、配置や判定の追跡を簡単にする。

読み込み方式が成立しない場合は、選択範囲の `.b3dm` 内のメッシュを変換・座標変換して Static Mesh として取り込む案を比較する。変換ツールの対応形式・ライセンス・テクスチャ・座標保持を小さなタイルで検証してから採用する。元データ形式が異なる PLATEAU 用インポータで、このZIPを直接読めるとは仮定しない。

### ゲーム実装

- 移動、ジャンプ判定、命中・撃破、進行状態は C++ を中心に実装する。
- Blueprint はキャラクター外見、演出、配置、調整値、UMG UI に使う。
- Third Person のカメラと入力を起点に、専用のゲームクラスを作る。
- 地図読み込みとゲームロジックを分離し、灰色のテストステージでも全ルールを検証できるようにする。
- 見た目の街とプレイ用の衝突を分ける。必要な地面・壁・屋上には安定した簡易コリジョンを用意し、表示タイルの読み込みやLOD変更で足場が消えないようにする。

## 4. ステップバイステップ

### Step 1 — 起動と作業基盤を確認する

1. UE 5.8 で既存プロジェクトを開き、C++ ビルドと Third Person マップの Play を確認する。
2. 既存プロジェクトをバックアップし、バージョン管理を用意する。生成物や大容量原本ZIPの扱いを決める。
3. `Content/Ninja/` とテスト用マップを用意する。
4. Windows PC を初期ターゲットにし、使用するエディタ・コンパイラ・プラグインの版を記録する。

**完了条件:** 起動、ビルド、通常移動・カメラ・ジャンプが動く。専用マップで実装を始められる。

### Step 2 — 地図の読み込みを小さく実証する（最初の技術的な関門）

1. ZIP の建物 LOD1 の tileset と参照ファイルを、相対パスを保って作業用に展開する。
2. Cesium for Unreal の UE 5.8 対応状況を確認し、採用版を固定する。
3. 地図確認用レベルでローカル tileset を読み込み、駅付近に基準点を設定する。
4. 既知の寸法の箱やキャラクターを置き、位置、向き、縮尺、標高を確認する。
5. 仮の地面を置き、建物の表示とキャラクターの衝突を検証する。画面外・LOD変更時の衝突の維持も調べる。
6. 小規模な Windows パッケージを作り、地図ファイルを同梱して起動する。開発マシンの絶対パスに依存しない読み込みを試す。
7. 不成立なら原因を切り分け、プラグインのビルド対応または小範囲の Static Mesh 化を比較し、方式を決める。

**成果物:** 読み込み実証レベル、採用方式、必要な版と設定、未解決事項を記した `doc/map-data-notes.md`。

**完了条件:** 少なくとも駅周辺の建物を正しい縮尺で表示でき、配布形式への道筋が確認できる。表示できただけで地図工程を完了扱いにしない。

### Step 3 — 灰色のステージで忍者の移動と3段ジャンプを作る

1. 専用 Character / Input Mapping を作り、移動、視点、走り、ジャンプを設定する。
2. 地上の1段目と空中の2・3段目を、一連のジャンプとして管理する。
3. 初期案として、各段の頂点付近で再入力すると次の段が成立する方式を採用する。許容幅は頂点の前後約0.15秒から調整する。
4. 2・3段目では鉛直速度を指定値に更新し、十分な高さと移動距離を得る。横方向の空中操作を残す。
5. 成功段数と「今押すと成功する」タイミングを短いエフェクトやUIで伝える。
6. 着地で段数をリセットする。長押しで自動連続発動しないようにし、4段目を禁止する。許容範囲外の入力は不発とし、その理由が分かる表示を用意する。
7. 10m、20m、30m級の箱と隙間を並べ、実測した到達高さ・距離を記録する。飛び越える対象は低〜中層の建物から選ぶ。

| 操作 | 仮割り当て |
| --- | --- |
| 移動 | WASD |
| 視点 | マウス |
| 走る | Shift を押している間 |
| ジャンプ / 次の段 | Space を押す |
| 手裏剣 | マウス左ボタン |
| ポーズ | Esc |

**完了条件:** タイミング成功で最大3段、失敗で次段不発、着地後に再試行できる。通常ジャンプでは越えられないテスト建物を、3段成功で越えられる。30 / 60 / 120 fps で成功判定が大きく変わらない。

### Step 4 — 池袋駅周辺を切り出し、歩ける街にする

1. 地図上で駅、街区、建物高さ、道路の収録範囲を目視確認する。駅周辺の約400m四方を候補に、3段ジャンプで楽しめる街区を選ぶ。
2. プレイ境界と、その外側の背景用バッファ範囲を決め、緯度経度の範囲・基準点・ローカル座標を記録する。
3. `boundingVolume.region` と対象範囲の交差を調べてタイル階層を選択する。角度の単位はラジアンとして扱う。
4. 選択したタイルの祖先、外部 tileset、メッシュ内の外部参照がある場合の参照先を保持し、切り出し先の相対 URI が全て解決するようにする。変換行列・境界・LOD関連値の整合も検証する。
5. 親タイルの粗いメッシュや境界にまたがるタイルは範囲外も含み得る。タイル単位の抽出と厳密な形状の切断を区別する。初期版は交差タイルを保持し、境界外は表示制御と背景バッファで処理する。
6. LOD1 を基準にし、見た目の改善が必要な場合だけ LOD2 を比較する。同じ建物のLOD1/LOD2を無条件に重ねて表示しない。
7. 道路 LOD3 が候補範囲を覆うか確認する。地面が不足する場所は簡易地面を追加し、必要なら別の地形ソースを調達する。都市データに歩行面が全て含まれるとは仮定しない。
8. 路面、壁、遊ぶ屋上に簡易コリジョンを用意する。読み込みタイル側と重複して判定しないように衝突設定を整理する。
9. 範囲の縁、地面の穴、復帰地点、カメラの遮蔽を確認する。

**成果物:** 切り出し用スクリプト、選択範囲の設定、参照検証結果、`L_Ikebukuro` の地図土台。

**完了条件:** 原本ZIPから同じ範囲を再生成できる。地上を走れ、対象の屋上に着地できる。高速移動やカメラ旋回で足場を失わない。選択範囲外のデータを削減できている。

### Step 5 — 黒忍者・赤忍者の外見と2種類の撃破を作る

1. 最初は既存スケルトンを利用した仮の外見で、黒い主人公と赤い敵を明確に区別する。続いて頭巾・覆面などを加え、忍者と分かる見た目にする。
2. 停止した敵1体で、下降中の主人公が頭上から接触したときだけ踏みつけ撃破する処理を作る。接触位置、下降速度、上面判定を組み合わせる。
3. 踏みつけ成功時は小さく跳ね返る。段数は着地までリセットしない初期ルールとし、無制限に上昇できないようにする。
4. 手裏剣をカメラ中央の照準方向へ投げる。照準線で狙い点を決め、手元からその方向に一定速度で直進させる。
5. 重力・追尾を無効にし、移動の Sweep で高速弾の命中を取る。主人公を除外し、壁・地面・最初の敵で消す。射程または寿命と投射間隔を設定する。
6. カメラが壁越しに狙っても、手元からの経路に壁があれば壁で止まるようにする。
7. 敵の撃破処理を共通化し、踏みつけと手裏剣が同時に当たっても撃破数を1回だけ加算する。
8. 側面接触、被ダメージ、無敵時間、落下時の復帰を作る。

**完了条件:** 両方の方法で1回ずつ撃破できる。横から触れても踏みつけ成功にならない。手裏剣は直進し、壁を通過しない。同時命中で二重計上しない。

### Step 6 — 敵の簡単な行動と遭遇を作る

1. 敵は「短い範囲を巡回 → 近くの主人公を追う → 接触攻撃 → 元の範囲へ戻る」の最小構成にする。
2. 遊べる地面・屋上の固定コリジョン上で移動経路を作る。屋上の敵は同じ屋上内に行動範囲を限定する。
3. 既存 Combat サンプルの StateTree を参考に、必要な状態だけを使う。屋上間の高度なジャンプ追跡は後回しにする。
4. 建物内への入り込み、屋上端からの落下、経路がない場合の停止・帰還を処理する。
5. まず3体の小区域で、走る・3段ジャンプ・踏む・投げるまでを通して遊べる状態にする。

**完了条件:** 敵が壁を抜けず、到達不能な場所に逃げ込まない。地上と屋上の遭遇で2種類の倒し方が使える。

### Step 7 — 5分で終わる進行とUIを作る

1. ゲーム状態を `準備 → プレイ中 → 勝利 / 敗北` に分ける。
2. 開始前に地図と足場の準備を確認し、操作説明と短いカウントダウンの後で300秒タイマーを始める。
3. 残り時間、残敵数、体力、ジャンプ段数・タイミング、照準を表示する。
4. 遠くの敵を探し回らなくて済むよう、方向マーカーを用意する。最後の1体が残った場合も見つけられるようにする。
5. 全滅で勝利、時間切れまたは体力0で敗北。最終撃破と時間切れが同じ更新で起きた場合は勝利を優先するルールに統一する。
6. 結果画面からリトライできるようにし、敵、主人公、時間、UIを初期化する。

**完了条件:** 開始から結果、リトライまで完結する。ポーズで時間が止まり、終了後の命中で結果が変わらない。

### Step 8 — 池袋の街に8体を配置し、遊ぶ順序を調整する

1. 地上での最初の撃破、低い屋上、中層の屋上をつなぐ経路を設計する。
2. 最初の1体は容易に手裏剣を当てられ、次の1体は踏みつけを試せる場所に置く。
3. 3段ジャンプの成功で移動時間を短縮できる場所を作る。実際の建物寸法に合わせて移動速度と各段の上昇量を調整する。
4. 3段ジャンプが苦手でも地上・低所から攻略を進められる補助経路を用意する。
5. 黒忍者の輪郭が街に埋もれない照明や縁取り、赤忍者を見つけやすい表示を整える。
6. 効果音、投射・命中・踏みつけ・ジャンプ成功の短い演出を加える。

**完了条件:** 初見の試遊で、目的と操作が伝わり、3〜5分でクリアを狙える。経路や敵を探すだけの時間が長すぎない。

### Step 9 — 性能と不具合を調整する

1. テストPCの CPU / GPU / メモリ、解像度、描画品質を記録する。
2. Windows・1080p・60 fps を暫定目標に、地上、高い屋上、高速移動、敵複数体の場面を計測する。
3. 必要に応じて LOD、テクスチャ、表示距離、影、Lumen / Ray Tracing の設定を調整する。
4. タイル待ち、メモリ使用量、コリジョン生成、NavMesh 更新に起因する停止を調べる。固定した足場と小範囲のAIを優先する。
5. 下の確認表を実施し、再現手順と修正を記録する。

**完了条件:** 記録したPCで1プレイを通せる。継続的な性能低下、地面抜け、進行不能がない。

### Step 10 — 配布ビルドを完成させる

1. 起動マップと GameMode を専用ゲームに設定する。
2. 選択した地図データを配布物に同梱する。外部ファイルとして読む場合は Non-UFS の配置等を検証し、実行ファイルから解決できるパスを使う。
3. 開発時の絶対パス、ローカルHTTPサーバー、エディタ、オンライン地図への依存を調べる。初期版は同梱データで完結させる。
4. 元データの配布ページと個別の利用条件を確認し、出典、加工したこと、キャラクターや音源等のクレジットを記載する。
5. 配布フォルダを別の場所に移し、可能なら別PCで起動し、オフラインで開始・勝敗・再プレイを確認する。
6. 操作説明、起動方法、既知の制約を添えて配布物を保存する。

**完了条件:** エディタなしで起動し、同梱した池袋の街を使って約5分のゲームを最後まで遊べる。

| A | Step 1〜2 | 現在のUE環境で地図を表示し、配布に使えるか |
| B | Step 3 | 走る・3段ジャンプそのものが楽しいか |

地図の表示実証は最初に行う。ゲームの操作は軽いテストマップで仕上げ、地図への統合時に到達距離を再調整する。正確な工数は Step 2 の技術検証後に見積もる。

## 6. 最低限の確認表

| 分野 | 確認内容 |
| --- | --- |
| 三人称操作 | 視点基準の移動、走り、狭い場所と壁際のカメラ |
| 3段ジャンプ | 成功・早すぎ・遅すぎ・長押し・4回目・着地後のリセット、fps差 |
| 建物越え | 通常ジャンプでは届かず、3段成功で越えられる実データ上の経路 |
| 踏みつけ | 下降中の上面接触で成功。上昇中・横・下からは成功しない |
| 手裏剣 | 空中投射、直進、壁で停止、射程、連射制限、自分への命中除外、高速命中 |
| 撃破 | 同時命中、死亡済みの敵への再命中で二重加算されない |
| 敵 | 赤色と忍者の外見、巡回・追跡・帰還、屋上端、障害物、到達不能地点 |
| 地図 | 縮尺・標高、道路の穴、屋上衝突、画面外やLOD変更後の足場、切り出し後の参照 |
| 進行 | 全滅、時間切れ、体力0、ポーズ、同時の勝敗条件、3回続けてリトライ |
| 復帰 | 落下・範囲外から安全に戻る。体力0なら敗北し、敵数を維持する |
| 配布 | 別フォルダ・オフラインで地図が読める。出典と加工表記が含まれる |

C++ の自動テストは、ジャンプの状態遷移、撃破の一度限りの通知、勝敗の競合など、結果を壊しやすい部分を対象にする。カメラ、地図の見え方、移動の気持ちよさは実機で確認する。

## 7. 実装時に確定する事項

- 池袋駅周辺の具体的な境界と駅舎・道路の収録状態。
- Cesium の採用版と UE 5.8 での動作、または変換方式の採用。
- 地図の必要なLOD、地面の補完方法、足場コリジョンの作り方。
- 3段ジャンプの許容タイミング、上昇量、走行速度、対象にするビルの高さ。
- 敵8体、体力3、400m四方という初期案の試遊による調整。
- 最終的な忍者モデルとアニメーションの調達・制作方法。
- 元地図データの配布元ページ、適用条件、必要な出典表記。

これらは計画を進めるための検証項目。最初の実装着手は Step 1 と Step 2 とする。
